THE CHALLENGE

When the leak is hidden,
the loss keeps flowing.

Water distribution systems are made of connected pipes and junctions. When a leak develops out of sight, identifying the affected section can be difficult. Teams need useful signals to decide where to investigate.

THE PROBLEM STATEMENT

How might we use pipeline pressure and flow patterns to identify unusual conditions and help locate hidden water leaks?

Undetected pipeline leaks can waste clean water, increase repair costs, and contribute to infrastructure damage. Direct inspection across an extensive network may take time. GRIDGUARD demonstrates a virtual monitoring workflow that makes a pipeline network visible, lets users create leak scenarios, and presents readings and investigation results in one interface.

WHY IT MATTERS

Water is a critical resource.

Better awareness of suspicious conditions can support investigation and help water managers prioritize where to look first.

THE CURRENT CHALLENGE

Detection is not the same as localization.

An unusual reading may suggest a problem. Determining which pipe caused it requires a separate localization method and validation.

OUR APPROACH

A pipeline network you can investigate.

GRIDGUARD combines a virtual water network, generated telemetry, and an interactive dashboard. The current prototype is designed to demonstrate the workflow and provide a foundation for independent anomaly detection and leak localization.

UNDER THE HOOD

Small stack. Clear purpose.

Each technology has a specific role in the prototype, from modeling the virtual network to presenting results in the browser.

CORE LANGUAGE Python

Runs the simulation logic, builds dashboard data, and connects the components.

NETWORK MODEL NetworkX

Represents the pipeline as connected junctions and pipe segments.

NUMERICAL READINGS NumPy

Generates illustrative pressure variation and simulated measurement noise.

WEB API Flask

Serves the web pages and exposes endpoints for dashboard and simulation actions.

USER INTERFACE HTML & CSS

Creates the dashboard structure and visual design for monitoring and investigation.

INTERACTIVITY JavaScript

Requests dashboard data, updates the display, and handles user interactions.

Prototype transparency

The current build uses simulated data. Its baseline detector reads the simulated leak label rather than independently inferring a leak from pressure and flow. The dashboard is a demonstration, not a validated real-world detection system. Independent anomaly detection, localization confidence, and physical sensor integration are future work.
